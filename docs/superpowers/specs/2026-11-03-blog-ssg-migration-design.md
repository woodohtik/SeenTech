# مدونة سِين — هجرة من CSR (Supabase) إلى صفحات ثابتة حقيقية (Build-time SSG) — مواصفة

**الحالة:** معتمدة من المستخدم (محادثة عصف ذهني بتاريخ 2026-11-03) — جاهزة لخطة التنفيذ.

**تَحِل محل:** `docs/superpowers/specs/2026-11-01-blog-system-design.md` بالكامل. ذلك التصميم (نظام مدونة CSR يُدار من `/admin/blog`، يُخزَّن في جدول `blog_posts` بSupabase، صفحات React عادية `BlogList.tsx`/`BlogPost.tsx` تجلب البيانات في المتصفح) **تم تنفيذه وشحنه فعلاً** في جلسة سابقة ومنشور على الإنتاج حالياً — لكنه لا يحقق الشرط الذي يطلبه `seen-blog-implementation-task.md`: محتوى يطلع من الخادم فعلياً (SSR أو صفحات ثابتة)، لا تركيب بالجافاسكربت.

## الخلفية

تسلّمت إدارة سِين تصميمين جاهزين (HTML كامل، تنسيق إنلاين) لمدونة تسويقية/SEO بتاريخ 3 نوفمبر 2026، مرفقَين في `seen-blog-reference/`:

- `01_المدونة_من_الخارج.html` — صفحة `/blog/` (الفهرس): بحث، محاور، مقالة بارزة، "ابدأ من هنا"، شريط مقابلات، آخر المقالات.
- `02_المقالة_من_الداخل.html` — قالب صفحة المقالة، مطبَّق فعلياً على مقالة حقيقية واحدة: "كيف تتابع طلبات الخياط من الاستلام للتسليم؟".
- `00_تسليم_لنعمان.md` — شرح التصميم الكامل من المصمم: مصدر البيانات (frontmatter)، الشرطان غير القابلين للتنازل، سلوك كل عنصر، الهوية البصرية.

مطلوب أيضاً (`seen-blog-implementation-task.md`): استبدال الدعوة للإجراء «احجز زيارة» بـ«ابدأ الآن» في 7 مواضع محددة بدقة عبر الملفين، برابط جديد `https://seentech.io` بدل `https://seentech.io/#book` — باستثناء صريح واحد لا يتغيّر.

**مواد ذكرها ملف التسليم كـ"مُسلَّمة مسبقاً خارج المحادثة" — تحقَّق أنها غير موجودة فعلياً في المستودع (فحص `Glob`، لا نتائج):** `build_blog.py` (السكربت المرجعي الذي أنتج الملفين)، `../md/` (مقالات Markdown حقيقية بفرونت ماتر)، `../html/` (JSON-LD جاهز لكل مقالة)، مجلد الأيقونات `06_العلامة_Brand/الهوية_البصرية_v5/الأيقونات/svg`، `../01_بنية_المدونة_ودليل_النشر.md`. **القرار المعتمد: نعيد التخطيط بدونها بالكامل — لا محتوى مقالات حقيقي في هذه المرحلة، بنية تحتية فقط.**

## القرارات المعتمدة (عبر AskUserQuestion، بالترتيب)

1. **مصير نظام الإدارة الحالي (`AdminBlog.tsx` + جدول `blog_posts`):** استبدال كامل — المصدر الجديد الوحيد للمحتوى هو ملفات Markdown في المستودع نفسه. لا نظامان متوازيان.
2. **نهج تحقيق الشرط المعماري (SSR/صفحات ثابتة):** صفحات ثابتة مولَّدة وقت البناء (**Build-time SSG**) — لا SSR ديناميكي عبر `server.ts` (الذي لا يملك أي بنية `renderToString` حالياً أصلاً).
3. **مصدر المحتوى:** لا مقالات Markdown حقيقية الآن. نبني **البنية التحتية فقط** (القوالب، منطق التوليد، التوجيه) — لا استخراج المقالة المضمَّنة في `02_...html` كمقالة حقيقية، ولا تأليف محتوى. المحتوى الحقيقي يأتي لاحقاً من الفريق.
4. **صفحات المحاور الثمانية بلا مقالات:** تُولَّد كلها دائماً (لا فلتر جافاسكربت)، بحالة "قريباً" مع بقية عناصر الصفحة (الهيدر، الشرائح، الهوية البصرية) حتى تصل مقالات حقيقية لذلك المحور.
5. **المعرّفات الناقصة (واتساب حقيقي، GA4، سناب شات، ميتا):** تُبنى البنية بقيم config قابلة للضبط لاحقاً دون تعديل كود القوالب — لا قيم وهمية مكتوبة مباشرة في القوالب.
6. **`og:image`:** **ضمن هذه المرحلة** — توليد صورة PNG واحدة قابلة لإعادة الاستخدام لكل مقالة وقت البناء (عنوان المقالة على خلفية كحلية بالمسطرة من الهوية البصرية).

## 1) طبقة المحتوى

### `content/blog/*.md` (مجلد جديد، فارغ ابتداءً)

ملف واحد لكل مقالة. Frontmatter (YAML) + جسم Markdown:

```yaml
---
title: "..."
meta_description: "..."
cluster: management   # أحد: management, orders, measurements, software, season, e-invoicing, womens, curtains
publish_date: "2026-11-03"
related:               # حتى 3 روابط slug لمقالات أخرى
  - "slug-1"
  - "slug-2"
---

**الجواب المختصر:** ...

## قسم أول
...

## وين تدخل منصة سين؟
...

> **عن منصة سين:** ...

## أسئلة شائعة
### سؤال أول
جواب...

## اقرأ بعد

## نموذج تتبع الطلب
| ... | ... |

تحرير: فلان، 2026-11-03
```

الرابط (`slug`) = اسم الملف بلا الامتداد (أحرف عربية مباحة فيه، لا تحويل للاتينية — يطابق قرار المصمم).

### `content/blog.config.ts` (جديد)

القيم القابلة للضبط لاحقاً — فارغة/placeholder افتراضياً، لا قيم وهمية:

```ts
export const blogConfig = {
  whatsappNumber: '', // دولي بلا +، مثال لاحقاً: '9665XXXXXXXX'
  ga4MeasurementId: '', // مثال لاحقاً: 'G-XXXXXXXXXX'
  snapchatPixelId: '',
  metaPixelId: '',
  ctaLabel: 'ابدأ الآن',
  ctaUrl: 'https://seentech.io',
};
```

قالبا الصفحتين يتحققان من فراغ كل قيمة ويتجاهلان حقن سكربت/رابط ذلك المصدر بصمت (لا خطأ بناء، لا رابط/سكربت مكسور) حتى تُضبَط القيمة الحقيقية.

### الفرق الجوهري عن المواصفة السابقة الملغاة

لا جدول `blog_posts`، لا RLS، لا رفع صور عبر `uploadImageToSupabase`، لا شاشة `/admin/blog`. المحتوى يُراجَع ويُنشَر عبر git (pull request عادي)، مطابقاً تماماً لطريقة عمل بقية المهمة الأصلية وما تطلبه المهمة الحالية.

## 2) سكربت التوليد `scripts/build-blog.ts`

يعمل بـ`tsx` (موجود فعلاً في المشروع)، يُستدعى كخطوة مضافة في `package.json`:

```json
"build": "vite build && tsx scripts/build-blog.ts && esbuild server.ts --bundle --platform=node --format=cjs --packages=external --sourcemap --outfile=dist/server.cjs"
```

يعمل **بعد** `vite build` (يكتب مباشرة داخل `dist/` الذي أنشأه Vite للتو) و**قبل** حزم الخادم (لا تبعية بينهما، لكن هذا الترتيب أبسط للقراءة).

### الخطوات

1. يقرأ كل ملفات `content/blog/*.md` عبر `gray-matter` (جديد، تبعية خفيفة لفصل frontmatter عن الجسم — لا يوجد بديل حالياً بالمشروع).
2. يُفسِّر جسم كل مقالة بموزِّع أقسام مخصَّص (`scripts/blog/parseArticleSections.ts`) قبل تمريره لـ`marked` (موجود فعلاً بالمشروع، `^18.1.2`) لتحويل كل قسم Markdown عادي إلى HTML:
   - أول فقرة تبدأ بـ«**الجواب المختصر:**» → صندوق منفصل فوق المقالة.
   - كل `##` → قسم مرقَّم، يغذّي الفهرس الثابت (TOC).
   - `## وين تدخل منصة سين؟` تحديداً → الصندوق الكحلي بزر «نوريك إياه في محلك» (**بلا تغيير في نصه أو رابطه** — قرار صريح من المؤسس)، يُنقَل لنهاية المقالة بعد آخر قسم.
   - `> **عن منصة سين:**` → صندوق منفصل.
   - `## أسئلة شائعة` و`###` تحتها → أكورديون + يُغذّي JSON-LD من نوع `FAQPage`.
   - `## اقرأ بعد` → عنوان قسم الكروت فقط؛ الكروت نفسها من حقل `related` بالـfrontmatter (لا من روابط داخل جسم Markdown).
   - أي `## نموذج ...` → إطار منقّط + زر «اطبع النموذج» (`window.print()` مع `@media print` يُخفي كل شيء عدا ذلك الجدول).
   - سطر يبدأ بـ«تحرير:» → يُحذَف من الجسم (يظهر أصلاً تحت العنوان من `publish_date`).
3. يحسب: مدة القراءة (`عدد كلمات الجسم بعد التفسير / 180`، بحد أدنى دقيقتين)، "آخر تحديث" (`publish_date`)، `canonical` (`https://seentech.io/blog/{slug}`).
4. يبني JSON-LD (`Article` + `FAQPage` إن وُجد قسم أسئلة شائعة) من نفس البيانات المُفسَّرة — **لا حاجة لمصدر `../html/` خارجي**، نولّده بأنفسنا الآن.
5. يستدعي `renderIndexPage()`/`renderCategoryPage()`/`renderArticlePage()` (قوالب TS، القسم 3 أدناه) ويكتب:
   - `dist/blog/index.html`
   - `dist/blog/{slug}/index.html` لكل مقالة
   - `dist/blog/category/{slug}/index.html` للمحاور الثمانية كلها (دائماً، حتى بلا مقالات)
   - `dist/blog/search/index.html` (قالب البحث، القسم 4)
   - `dist/blog/search-index.json` (`[{slug, title, excerpt, cluster}]`)
   - `dist/blog/og/{slug}.png` (القسم 5)
   - `dist/sitemap.xml` و`dist/robots.txt` (القسم 6)

فشل تفسير أي ملف مقالة واحد (frontmatter ناقص، `cluster` غير معروف) **يوقف البناء بخطأ واضح** يسمّي الملف والمشكلة — لا تجاهل صامت لمقالة معطوبة في مدونة منشورة فعلاً.

## 3) القوالب — ميناء حرفي للتصميم المرجعي

`scripts/blog/templates/indexPage.ts`، `categoryPage.ts`، `articlePage.ts` — كل واحدة دالة TS تُرجِع نص HTML كامل. تبدأ كنسخ حرفي من المرجعين (نفس `<head>`، نفس كتلة `<style>` الإنلاين، نفس الـclasses، نفس أيقونات SVG المضمَّنة) — **لا تصميم جديد، لا استخلاص لملف CSS مشترك يغيّر المخرجات البصرية**. فقط الأجزاء الديناميكية (قائمة أعلاه) تصير معاملات دالة بدل نص ثابت. `categoryPage.ts` نسخة من `indexPage.ts` بعنوان/وصف محور واحد بدل الكل، وحالة "قريباً" إن كانت قائمة مقالاته فارغة.

### استبدال الدعوة للإجراء (مطبَّق داخل القوالب، مرة واحدة، وليس استبدال نص وقت التوليد)

كل المواضع السبعة المذكورة بدقة في `seen-blog-implementation-task.md` (هيدر الصفحتين، لوحة الدعوة أسفل صفحة المدونة، الزر الثابت أسفل الشاشة بالجوال في الصفحتين، الكرت الثابت يسار المقالة بما فيه `aria-label`) تُكتَب في القوالب مباشرة كـ`{blogConfig.ctaLabel}` (="ابدأ الآن") بدون «ربع ساعة»، ورابط `{blogConfig.ctaUrl}` (=`https://seentech.io`، بلا `#book`). **الاستثناء الوحيد:** زر «نوريك إياه في محلك» وسط المقالة — نص ورابط ثابتان غير مرتبطين بـ`blogConfig`، كما كانا في المرجع تماماً، بانتظار تأكيد الفريق لاحقاً (مثل ما ينص الملف الأصلي).

## 4) البحث — الاستثناء الوحيد من "كله ثابت"

استعلام بحث حر (`?q=...`) لا يمكن تجهيزه مسبقاً وقت البناء بتعريفه. `dist/blog/search/index.html` صفحة ثابتة (هيكل الصفحة، الهيدر، كل شيء عدا النتائج) تحمل سكربتاً صغيراً (`<script>` إنلاين، بلا React، بلا حزمة) يجلب `search-index.json` (نفس الأصل، لا طلب شبكي خارجي) ويُفلتر العناوين/الأوصاف في المتصفح. هذا **تحسين تدريجي فوق** صفحة ثابتة أصلاً — لا يخالف الشرط غير القابل للتنازل، لأن صفحات المقالات والمحاور (المحتوى الفعلي المطلوب فهرسته لمحركات البحث) تبقى HTML خام بالكامل بلا أي اعتماد على جافاسكربت لإظهار محتواها.

## 5) `og:image` — توليد PNG وقت البناء

تبعيتان جديدتان: `satori` (JSX/تنسيق شبيه بـCSS → SVG) و`@resvg/resvg-js` (SVG → PNG) — نفس الثنائي الذي تستخدمه `@vercel/og` داخلياً، لكن مستدعى مباشرة هنا لأن التوليد وقت البناء لا عند الطلب (لا حاجة لدالة Vercel Edge). `scripts/blog/ogImage.ts`: تخطيط واحد مشترك (عنوان المقالة، خلفية كحلية `#0E2A42`، عنصر "المسطرة" الزخرفي — مُستخرَج من SVG المضمَّن فعلاً داخل الملفين المرجعيين، لا صورة ستوك ولا أصل جديد) يُصدِّر `dist/blog/og/{slug}.png` لكل مقالة، ويُشار إليه من وسم `og:image` بكل صفحة مقالة.

## 6) `sitemap.xml` و`robots.txt`

يُولَّدان في نفس خطوة البناء من نفس قائمة المقالات + روابط المحاور الثمانية الثابتة + `/blog/`. `robots.txt` يسمح بـ`/blog/` ويشير لموقع `sitemap.xml`.

## 7) التوجيه — Vercel

`vercel.json` الحالي:

```json
{ "source": "/((?!api/).*)", "destination": "/index.html" }
```

يلتهم `/blog/*` ضمن تطبيق React أحادي الصفحة (قبل هذه المهمة، هذا كان مقصوداً — المدونة كانت CSR). بعد الهجرة، يجب استثناء `/blog` صراحة حتى يخدم Vercel الملفات الثابتة المولَّدة مباشرة لا `index.html`:

```json
{ "source": "/((?!api/|blog(?:/|$)).*)", "destination": "/index.html" }
```

يُتحقَّق من هذا عملياً بعد النشر بقراءة نص خام (`curl`/أداة بلا تنفيذ جافاسكربت) — نفس الفحص الذي أجراه المصمم ونبّه لغيابه في `staging.seentech.io` الحالي.

## 8) Service Worker (PWA) — استثناء صفحات المدونة من الـprecache

`vite.config.ts` الحالي يستثني فعلاً حزم SaaS/السوبر أدمن من `globPatterns` الخاصة بـWorkbox (نفس النمط المطبَّق هنا). نضيف استثناءً مماثلاً لـ`blog/**` — صفحات المدونة الثابتة ليست جزءاً من قشرة التطبيق (app shell)، ولا داعي لتثبيتها مسبقاً في ذاكرة التخزين المؤقت لكل زائر تطبيق.

## 9) إزالة النظام القديم (لا استبقاء مزدوج)

- حذف: `src/components/AdminBlog.tsx`، `src/pages/BlogList.tsx`، `src/pages/BlogPost.tsx`، `src/services/blogService.ts` + اختباره.
- حذف المسار `/admin/blog` ومساري `/blog`، `/blog/:slug` الحاليين (React Router) من `App.tsx`.
- **جدول `blog_posts` وsticky bucket التخزين الخاص به في Supabase (migrations `20261108000000`، `20261109000000`، `20261110000000`): يُتركان كما هما في قاعدة البيانات مؤقتاً، بلا أي كود تطبيق يستخدمهما بعد هذه المهمة.** لا مايجريشن حذف ضمن هذه المواصفة — أي محتوى نُشر فعلاً على الإنتاج عبر `AdminBlog.tsx` سابقاً يحتاج مراجعة يدوية (هل يُنقَل لملف Markdown؟ يُؤرشَف؟) قبل أي حذف فعلي للجدول، وهذا قرار منفصل يحتاج تأكيداً صريحاً لاحقاً — عملية حذف بيانات لا تُتخذ ضمنياً.
- تعديل وحيد على `src/components/LandingPage.html`: الرابط لصفحة `/blog` موجود من المواصفة السابقة (القسم 4 هناك) — يبقى كما هو، يشير الآن لصفحة ثابتة حقيقية بدل صفحة CSR، بلا أي تعديل إضافي مطلوب على `landing-bridge.js`.

## 10) الاختبار والقبول

- اختبارات وحدة (TDD) لموزِّع الأقسام (`parseArticleSections.ts`): كل حالة من القسم 2 (صندوق الجواب المختصر، الأقسام، صندوق "وين تدخل"، صندوق "عن منصة سين"، أكورديون الأسئلة، "اقرأ بعد"، إطار النموذج القابل للطباعة، حذف سطر "تحرير:") — عينات نصية مصغَّرة، لا تعتمد على ملفات حقيقية.
- اختبارات وحدة لحساب: الرابط، مدة القراءة، "آخر تحديث"، وجدول توجيه المحاور الثمانية.
- **مقالة اختبار واحدة** (`content/blog/__fixture-test-article.md` أو ما يماثلها بتسمية واضحة كعينة اختبار لا محتوى حقيقي) تُستخدَم فقط لإثبات أن خط الأنابيب الكامل (frontmatter → صفحة) يعمل فعلياً من طرف لطرف — **لا تُعامَل كمقالة حقيقية منشورة**، ولا تُدرَج ضمن القائمة النهائية الفعلية عند وصول محتوى حقيقي (تُحذَف أو تُستبعَد من `sitemap.xml`/الفهرس حينها).
- فحص قبول بعد البناء: تشغيل `npm run build` ثم قراءة `dist/blog/index.html` وصفحة محور واحدة على الأقل بأداة نصية خام (لا متصفح، لا تنفيذ جافاسكربت) والتأكد من ظهور نص حقيقي — يُضمَّن كسكربت تحقق (`scripts/verify-blog-ssr.ts` أو ضمن اختبار CI)، لا فحصاً يدوياً فقط.

## خارج النطاق لهذه المرحلة (بالاتفاق)

- أي محتوى مقالات حقيقي — ينتظر الفريق.
- القيم الحقيقية لرقم الواتساب، معرّفات GA4/سناب شات/ميتا — تُضبَط لاحقاً في `content/blog.config.ts` بلا تعديل كود.
- مراجعة/نقل أي محتوى منشور فعلاً سابقاً عبر `AdminBlog.tsx` على الإنتاج، وحذف جدول `blog_posts` نفسه.
- أي تعديل على زر «نوريك إياه في محلك» وسط المقالة.
- تصنيفات/وسوم أبعد من المحاور الثمانية الثابتة، جدولة نشر مستقبلية، لغات أخرى — نفس استبعادات المواصفة السابقة، ما زالت سارية.
