## السياق والهدف

طلب المؤسس إضافة إدخال صوتي في ثلاث نقاط: البحث، إدخال المقاسات، والإدخال العام للبيانات.

فحص الكود الفعلي (وكيل بحث منفصل هذه الجلسة) أكّد:
- **لا يوجد أي كود صوتي في المشروع حالياً** — لا مكتبات (`package.json` خالٍ من أي حزمة صوت/تعرّف كلام)، لا استخدام لـ`SpeechRecognition`/`getUserMedia` في أي ملف. مشروع جديد تماماً.
- كل شاشات البحث الحالية (`POS.tsx:114`, `Orders.tsx:315`, `Customers.tsx:~99`, `InventoryManager.tsx:150`) هي فلترة نصية بسيطة (`useState` + `.filter()`/`useMemo` على قائمة محمَّلة مسبقاً مباشرة في الذاكرة) — لا استعلام خادم. حقن نص في متغيّر الحالة الموجود يكفي؛ صفر تغيير في منطق الفلترة.
- `IconInput` (`src/components/ui/IconInput.tsx`) مكوّن إدخال نصّي مشترك مستخدَم في 34+ ملفاً، يدعم فعلاً خانة أيقونة نهاية (end icon) — نقطة إلحاق طبيعية لزر مايك.
- شاشة المقاسات الرقمية الفعلية هي `ThobeMeasurementSelector.tsx` (لا `VisualMeasurements.tsx`، وهو محدِّد سمات أسلوب فقط بلا أرقام): 8 حقول `<input type="number" step="0.1">` (الرقبة، الكتف، الصدر، الخصر، الأرداف، الكم، الطول، عرض الأسفل)، مع `handleInputChange` تطبّع القيمة بـ`Math.max(0, parseFloat(value) || 0)`.
- لا يوجد نمط موجود في المشروع لطلب/رفض صلاحية المايك (`ScannerModal.tsx` يفوّض كل شيء لمكتبة `html5-qrcode` الخارجية لصلاحية الكاميرا) — سيُصمَّم من الصفر هنا.

**قرارات المؤسس (عبر `AskUserQuestion`):**
1. الأولوية: البحث والمقاسات بنفس الأهمية، بلا ترتيب.
2. لهجة التعرّف الصوتي: **العربية فقط** (`ar-SA`) — لا دعم لـEnglish/Urdu في هذه الميزة حتى لو كانا لغتي واجهة مدعومتين في باقي التطبيق.
3. إدخال المقاسات: **معالج صوتي متتابع** (الشاشة تسأل حقلاً حقلاً، لا جملة واحدة تذكر كل المقاسات).
4. سؤال المعالج يُنطَق بصوت الجهاز (Text-to-Speech) فعلياً، لا نص مكتوب فقط — المستخدم يداه مشغولتان بالقماش.
5. الإدخال الصوتي العام (غير البحث والمقاسات) مرحلة أولى محدودة الحقول: اسم العميل + ملاحظاته (`Customers.tsx`)، اسم المنتج (`InventoryManager.tsx`)، اسم الموظف (`AddEmployeeModal.tsx`)، ملاحظات الطلب (`Orders.tsx`).

## خارج النطاق (صريح)

- أي لغة غير العربية للتعرّف الصوتي (قرار مؤسس صريح، وليس قيد تقني — Web Speech API تدعم `en-US`/`ur-PK` فعلياً لو تغيّر القرار لاحقاً).
- أي خدمة تحويل كلام-لنص خارجية مدفوعة (Google Cloud Speech، Whisper API، إلخ) — Web Speech API المجانية المدمجة في المتصفح كافية ولا حاجة خادم إطلاقاً.
- تفعيل المايك على حقول الهاتف/السعر/الباركود/كلمة المرور أو أي حقل حسّاس/رقمي دقيق خارج قائمة البند 5 أعلاه.
- اختبار آلي لتعرّف صوتي حقيقي (الصوت الفعلي عبر ميكروفون) — غير ممكن في بيئة الاختبار الحالية (`vitest`/`jsdom` لا تملك Web Speech API على الإطلاق؛ محاكاتها (mock) هي أقصى ما يمكن أتمتته).
- أي شاشة/حقل آخر غير المذكور صراحةً أعلاه (لا توسّع تلقائي لاحقاً بلا طلب صريح جديد).

## البنية التقنية

كل شيء من جانب المتصفح بالكامل، بلا أي تعديل على الخادم أو قاعدة البيانات.

### 1) `useSpeechRecognition` (hook جديد، `src/hooks/useSpeechRecognition.ts`)

يغلّف `window.SpeechRecognition || window.webkitSpeechRecognition`، وضع "جملة واحدة" (`continuous: false`, `interimResults: false`, `lang: 'ar-SA'`).

```ts
interface UseSpeechRecognitionResult {
  isSupported: boolean;   // false لو كلا الكائنين غير موجودين في window -- يُستخدَم لإخفاء زر المايك كلياً
  isListening: boolean;
  transcript: string | null;
  error: 'no-speech' | 'not-allowed' | 'network' | 'other' | null;
  start: () => void;
  stop: () => void;
}
function useSpeechRecognition(): UseSpeechRecognitionResult
```

يُنشئ كائن `SpeechRecognition` جديداً في كل استدعاء `start()` (تجنّب أي حالة متسرّبة بين استخدامات)، ويُنظَّف (`abort()`) عند `unmount` أو استدعاء `stop()`.

### 2) `parseArabicNumber(text: string): number | null` (دالة نقية، `src/utils/parseArabicNumber.ts`)

تُحوِّل كلاماً عربياً منطوقاً مُحوَّلاً لنص إلى رقم:
1. تُجرِّب `parseFloat` مباشرة أولاً بعد تطبيع الأرقام العربية-الهندية إن وُجدت (المتصفح قد يُرجِع "٤٠" أو "40" حرفياً لأرقام بسيطة).
2. إن فشل: قاموس كلمات عربية → أرقام يغطي المدى الواقعي للمقاسات (0–300): آحاد (صفر..تسعة)، عشرات (عشرون..تسعون)، المركّب منها بصيغة "و" (خمسة وأربعون)، مئة/مئتان/ثلاثمئة + العشرات/الآحاد المركّبة معها.
3. غير قابل للتفسير (كلام غير متوقَّع، صمت، إلخ) ← `null` — المستدعي (المعالج) يعرض خياراً لإعادة المحاولة أو الإدخال اليدوي، لا يُعبّئ الحقل بقيمة خاطئة أبداً.

لا دعم كسور عشرية منطوقة في الإصدار الأول (مثل "أربعين ونص") — الحقول الرقمية تبقى قابلة للتعديل اليدوي الدقيق بعد التعبئة الصوتية دوماً، فهذا القيد غير حادّ.

### 3) ربط البحث والإدخال العام — خاصية جديدة على `IconInput`

```ts
interface IconInputProps {
  // ...الموجود فعلاً
  voiceEnabled?: boolean; // اختياري، يُضاف خاصية جديدة فقط -- لا كسر لأي استخدام حالي
}
```

عند `true` و`useSpeechRecognition().isSupported`: زر مايك صغير في خانة الأيقونة النهائية الموجودة فعلاً. ضغطه يستدعي `start()`، والنتيجة (`transcript`) تُمرَّر مباشرة لـ`onChange` الموجود للمكوّن (نفس مسار الكتابة اليدوية تماماً، فلا حاجة لأي منطق فلترة/حفظ جديد في أي شاشة تستهلكها).

نقاط التفعيل (سطر واحد في كل موضع):
- بحث: `POS.tsx`, `Orders.tsx`, `Customers.tsx`, `InventoryManager.tsx`.
- إدخال عام: اسم/ملاحظات العميل (`Customers.tsx`)، اسم المنتج (`InventoryManager.tsx`)، اسم الموظف (`AddEmployeeModal.tsx`)، ملاحظات الطلب (`Orders.tsx`).

### 4) معالج المقاسات الصوتي — `VoiceMeasurementWizard` (مكوّن جديد)

يُستدعى من `ThobeMeasurementSelector.tsx` عبر زر "تعبئة المقاسات بالصوت" جديد بجانب حقول الإدخال الحالية.

**منطق التسلسل (دالة منفصلة قابلة للاختبار بعزل عن الصوت، `getNextMeasurementStep`)**: قائمة ثابتة من 8 عناصر `{ key, labelAr }` بالترتيب (الرقبة، الكتف، الصدر، الخصر، الأرداف، الكم، الطول، عرض الأسفل)، ومؤشر موضع حالي.

**لكل حقل بالترتيب:**
1. `speechSynthesis.speak(new SpeechSynthesisUtterance('قل مقاس ' + labelAr))` — عربي، صوت الجهاز الافتراضي.
2. عند `onend` لنطق السؤال: `useSpeechRecognition().start()` تلقائياً (استماع فعلي يبدأ بعد انتهاء السؤال مباشرة، لا تداخل صوتي).
3. عند توفّر `transcript`: `parseArabicNumber(transcript)`.
   - قيمة صالحة: تُعبّئ **حقل الرقم الموجود فعلياً** في `ThobeMeasurementSelector` (نفس `handleInputChange`، لا حالة بيانات موازية) + عرض "✓ (الحقل): (القيمة)" لمدة ~1.5 ثانية قابلة للمس للتصحيح الفوري قبل الانتقال التلقائي للحقل التالي.
   - `null` أو خطأ تعرّف: عرض "لم أفهم، حاول مرة أخرى" + زر إعادة محاولة لنفس الحقل (لا انتقال تلقائي لحقل خاطئ).
4. بعد الحقل الثامن: المعالج يُغلَق تلقائياً؛ كل الحقول تبقى قابلة للتعديل اليدوي العادي بعدها كما هي اليوم — المعالج أداة تعبئة سريعة فقط، ليست مسار بيانات مستقلاً.

في أي لحظة: زر "إلغاء" يوقف المعالج فوراً (`speechSynthesis.cancel()` + `useSpeechRecognition().stop()`) ويترك الحقول بما عُبِّئ حتى تلك اللحظة.

## معالجة الأخطاء

- **المتصفح لا يدعم Web Speech API** (مثل Firefox): `isSupported === false` منذ البداية — زر المايك/زر المعالج الصوتي لا يظهران إطلاقاً في تلك الحالة، لا رسالة خطأ مقلقة، الإدخال اليدوي يعمل كالعادة دوماً.
- **رفض صلاحية المايك**: `error === 'not-allowed'` — رسالة واضحة "يحتاج الوصول للمايكروفون. فعّله من إعدادات المتصفح." بدل فشل صامت.
- **صمت/عدم فهم** (`no-speech` أو فشل `parseArabicNumber`): رسالة "لم أسمع/أفهم شيئاً، حاول مرة أخرى" + إمكانية إعادة المحاولة فوراً، أبداً لا تعبئة بقيمة افتراضية أو فارغة بصمت.
- **خطأ شبكة** (`network`): Web Speech API في Chrome تعتمد فعلياً على خادم جوجل لمعالجة الصوت (ليست محلية بالكامل) — رسالة "تحقّق من الاتصال بالإنترنت" عند هذا الخطأ تحديداً.
- **`speechSynthesis` غير متاح أو فشل نطق السؤال** (بعض إعدادات النظام بلا أصوات مُركَّبة): المعالج يعرض نص السؤال كتابةً على الشاشة ويبدأ الاستماع مباشرة بلا انتظار نطق — تدهور لطيف (graceful degradation)، لا توقّف كامل للمعالج.

## الاختبار

Web Speech API **غير متاحة إطلاقاً** في بيئة الاختبار (`vitest` + `jsdom`) — لا يوجد `window.SpeechRecognition` فيها حقاً، فلا يمكن اختبار استماع صوتي حقيقي آلياً بأي حال. ما يُختبَر بـTDD حقيقي (فشل أولاً، ثم تنفيذ):

1. **`parseArabicNumber`** (`src/utils/parseArabicNumber.test.ts`): أرقام مفردة، مركّبة بـ"و"، مئات ومركّباتها، أرقام من المتصفح مباشرة ("40")، أرقام هندية-عربية ("٤٠")، نصوص غير مفهومة ← `null`، نص فارغ ← `null`.
2. **`useSpeechRecognition`** (`src/hooks/useSpeechRecognition.test.ts`): صنف `SpeechRecognition` وهمي (mock class) يُحقَن في `window` قبل كل اختبار — تحقّق من `isSupported` (موجود/غير موجود)، دورة `start → isListening=true → onresult → transcript يتحدّث → isListening=false`، ومسارات الخطأ (`onerror` بكل الأنواع الأربعة أعلاه).
3. **`getNextMeasurementStep`** (منطق تسلسل المعالج، معزول تماماً عن الصوت): يبدأ بالحقل الأول، يتقدّم بالترتيب الصحيح، يتوقف بعد الثامن، لا يتخطّى حقلاً بقيمة `null`.

الاختبار اليدوي الفعلي (ميكروفون حقيقي، لهجات/لكنات متنوّعة، ضجيج خلفية) يبقى ضرورياً بعد التنفيذ على `staging` — سيُطلَب من المؤسس تجربته مباشرة.
