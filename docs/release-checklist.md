# قائمة «جاهز للإنتاج»

`seen-stability-guardrails-task.md`، المرحلة 5. قرار المؤسس (السؤال 2، الافتراضي).

**النسخة جاهزة للإنتاج فقط إذا تحقق كل ما في هذه القائمة.** وبدونها ما أحد يقول «جاهز»، لا Claude Code ولا المؤسس.

## أ. الآلي (قبل الفحص اليدوي)

- [ ] **الفحص (CI) أخضر على `staging`** لآخر commit، بكل وظائفه:
  - `build-and-lint`: الأنواع، وESLint، وفحص الحزم، والاختبارات، والبناء، وحجم الحزمة.
  - `pgtap`: اختبارات قاعدة البيانات، و**لقطة الدوال مطابقة**.
  - `e2e`، و`golden` (المسارات الذهبية، حين تُفعَّل).
- [ ] **Sentry نظيف على staging لمدة 24 ساعة:** ما فيه خطأ **جديد** في `seen-web` أو `seen-server` بالبيئة `staging`.
- [ ] **كل migration جديدة طُبّقت على staging، ولها ملف postcheck** في `scripts/release/` نجح هناك.
- [ ] `npx tsx scripts/verify-deploy.ts --host staging.seentech.io --ref origin/staging`: يقول OK.

## ب. الفحص اليدوي (15 دقيقة، على جهاز حقيقي)

لابتوب للخطوات 1–6، وجوال للخطوة 7. **على staging.seentech.io بالمحل التجريبي، لا بيانات حقيقية.**

1. [ ] **الدخول:** بالإيميل وكلمة المرور، ثم رمز موظف (PIN).
2. [ ] **بيع في نقطة البيع:** صنف جاهز + ثوب تفصيل، دفع كاش، والفاتورة الضريبية المبسطة ظاهرة.
3. [ ] **طلب تفصيل حتى التسليم:**
   - عميل، ثم مقاسات بالترتيب المعتمد، ثم عربون.
   - قص (نافذة القماش، والرصيد ينقص مرة واحدة)، ثم خياطة، ثم جاهز، ثم سداد المتبقي، ثم تسليم.
4. [ ] **طباعة حقيقية:** إيصال 80mm على الطابعة الفعلية، وإعدادات الفاتورة منعكسة عليه.
5. [ ] **واتساب:** إرسال رسالة استلام طلب تفتح بالقالب الصحيح ورقم العميل الدولي.
6. [ ] **إقفال الوردية:** الرصيد المتوقع يطابق الكاش المعدود.
7. [ ] **من الجوال:** فتح رابط متابعة الطلب، ورابط المقاسات، ثم الحفظ.

- أي migration يطبّقها المؤسس على الإنتاج قبل دمج الكود، ثم postcheck الإنتاج.
